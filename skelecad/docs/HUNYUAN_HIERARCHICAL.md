# 情報を省略しない階層方式（2026-09-05）

`image_workflow.inference_decoder`の既定を`hierarchical_full`にしました。
FlashVDMの階層的に表面付近を探索する考え方を利用し、Adaptive KV Selectionによる形状情報の間引きは行いません。
要求解像度384をそのまま使い、50ステップ・guidance 5.0・FP16・Hunyuan 2.1の重みを維持します。
上流ソースは改変せず、`src/hunyuan_decoder.py`に独立したデコーダーを実装しました。

## 採用基準：ユーザー提供の複雑な骨格モデル

品質判断はティラノサウルスとプテラノドンを主とします。ロボット画像は補助的な動作確認であり、
それだけでは新方式を採用しません。細い骨、指、歯、肋骨、関節、頭蓋骨の穴を含む形状で、
通常方式に対する劣化を確認します。既存の意図された穴と、開いたメッシュ境界は区別します。

ユーザー提供のティラノサウルス画像（`assets/image_to_3d/20260830_dfba1098/source_original.png`）を
既存の背景処理に通し、同じlatentから通常方式・新方式・FlashVDMを比較しました。

| ティラノサウルス | Seed 3407 | Seed 3408 |
| --- | ---: | ---: |
| 通常方式：表面計算 | 123.19秒 | 126.46秒 |
| 新方式：表面計算と出力検査 | 6.27秒 | 6.42秒 |
| 通常方式：共通拡散＋表面計算 | 216.26秒 | 219.42秒 |
| 新方式：共通拡散＋表面計算と検査 | 99.34秒 | 99.38秒 |
| 後処理後の面数（両方式一致） | 379722 | 392180 |
| 後処理後の連結成分数（両方式一致） | 4 | 3 |
| Euler数（両方式一致） | -190 | -196 |
| 後処理後のSTL | SHA-256完全一致 | SHA-256完全一致 |

Seed 3407のSTL SHA-256は`25d2b8b48b640b2d2d15c77ecb9d19445bd83eb81ddee33d0a63d5af50bf5681`、
3408は`ea8a1a22eb752ed54a76382fbb55132bf108243593b59f599e2c74caf9f21173`です。
両方式とも既存の退化面除去後に閉じたメッシュとなり、原点・サイズ・頂点・面・穴の構造が一致しました。
元の通常方式にも複数の成分があり、新方式でそれを結合・修復したわけではありません。
推論部分を約54–55%短縮し、通常方式への切り替えは発生しませんでした。
FlashVDMは両Seedで後処理後も開いた境界が残り、3407では最大約2.02 mmの頂点距離差が出ました。

プテラノドンは以下の「骨格モデル」の検証を指します。主たる検証範囲は複雑な2画像・計3条件です。
ティラノのログ・比較JSON・STL・プレビューは`.runtime/hunyuan-complex-check/trex/`に保存しています。
再検証は推論環境で`tools/benchmark_hunyuan_decoders.py --input INPUT --output-dir NEW_DIRECTORY --hunyuan-root HUNYUAN_ROOT --seeds 3407 3408`を使用します。
このツールは各Seedのlatentも保存します。測定後に追加した保存処理であり、今回のティラノの実行にはlatent保存ファイルはありません。

## 骨格モデルで比較した7方式

穴とバリが出た同じ処理済み入力、Seed 3407のlatentを共通にし、表面計算を比較しました。
時間は拡散や読み込みを含まず、VAEからの表面生成と書き出し前のGPU同期までです。
元の通常方式は推論全体220.79秒で、表面計算には約125秒を要しました。

| 方式 | 表面計算 | 結果 |
| --- | ---: | --- |
| FlashVDM既定のmean | 4.18秒 | 開いた境界142辺、腕と足首に約1.5–1.6 mmの局所差 |
| 情報選択をmergeへ変更 | 4.00秒 | 境界55辺が残存 |
| 情報を約2/3残す | 4.48秒 | 境界なしだが腕に最大約0.65 mmの局所差 |
| FlashVDM探索＋全情報 | 4.86秒 | 境界なし、腕・足首の局所差は最大約0.075 mm |
| 既定情報選択＋探索範囲拡大 | 5.08秒 | 境界は閉じたが腕に最大約2.09 mmの局所差 |
| 全情報＋探索範囲拡大 | 6.49秒 | 境界なし、通常幅に対する明確な改善なし |
| 元の解像度を保持する階層方式、座標型を補正 | 5.59秒 | 通常の後処理後、通常方式と面数が一致。最大頂点差0.000069 mm |

範囲拡大は、細分化後の探索マスク拡張を2回から4回へ変更したものです。
情報増量は3072中2048、512中384、それ以外は2/3のKVを保持しました。
局所差は腕・足首の各半径6 mm内から各方向最大3000頂点を抽出し、相手の三角形面まで測定しています。
穴が閉じているだけではバリや変形がないことを保証できないことも確認しました。

## 階層方式の座標不具合

上流の`HierarchicalVolumeDecoding`は、整数の格子インデックスの型を使って格子間隔を作っています。
このため1未満の間隔がゼロへ切り捨てられ、細分化後に誤った座標を評価し、最終段階で空のリストとなっていました。
検証用に座標計算をFP32へ補正すると正常に動きました。
採用実装は最初からFP32で座標を計算し、モデルへ渡すときにFP16へ変換します。
探索マスクは畳み込みによるカウントではなく最大値プーリングで拡張します。

## 採用実装の実測

独立実装を改めて検証しました。骨格モデルの表面計算は5.55秒、PyTorch最大割当8051 MiB・予約8574 MiBでした。
ロボット画像では生成スクリプト全体を実行し、推論102.53秒、読み込み込み140.85秒、
最大割当8061 MiB・予約9118 MiBでした。ロボットの従来値は推論220.47秒、全体262.12秒です。
全体で約46%、推論部分で約53%短縮しました。骨格の新方式の全体時間は今回測定していません。
PyTorchの値にはデスクトップなど他プロセスのGPUメモリは含まれません。

| 通常の120 mm後処理後 | 骨格 | ロボット |
| --- | ---: | ---: |
| 面数（通常方式・採用方式とも） | 202040 | 461140 |
| 閉じたメッシュ・面の向き・成分数 | 正常、1成分 | 正常、1成分 |
| 最近傍頂点の最大差 | 0.000069 mm | 0.000046 mm |
| 双方向表面サンプルの最大差 | 0.000018 mm | 丸め誤差程度 |

骨格の腕と足首の拡大画像も確認し、穴とバリはありませんでした。
通常方式と採用方式では除去対象の小さな破片数に違いがありますが、表の比較は既存の後処理後の形状です。
表面比較は各方向5000点のサンプリングであり、全表面の誤差上限を証明しません。
この節の測定はプテラノドンと補助用ロボットの各Seed 3407です。階層探索には微小な独立形状を粗い段階で見落とす可能性が残るため、
別の画像の細部まで通常方式と一致する保証はありません。テクスチャ生成は対象外です。

## 異常時の挙動と設定

新方式で例外、非有限座標、空メッシュ、開いた境界、面の向きの異常が出た場合、
同じlatentを通常方式で展開し直します。画像からの拡散生成をやり直す必要はありません。
その場合は時間が長くなり、記録の`actual_decoder`が`vanilla`、`decoder_fallback_reason`に理由が入ります。
閉じたまま起きる欠落や形状変化を、この検査だけで完全検知することはできません。

`config/parameters.json`の`image_workflow`は`inference_decoder: hierarchical_full`、`num_chunks: 8000`です。
単独CLIで指定する場合は`--decoder hierarchical_full`を使用します。CLIの省略時は互換性のため`vanilla`です。
通常方式へ戻す場合は`vanilla`にし、時間目安`volume_decoding`を125へ戻してください。
既存ジョブの設定と生成物は変更していません。新しいジョブから適用します。

モデル不要のテストは、推論環境のPythonで`tools/test_hunyuan_decoder.py`を実行します。
座標の正しさと球面の探索範囲、同じlatentによる通常方式への切り替えを検査し、2件合格しました。
画像ワークフロー29件も合格しています。
生成データ、測定値、比較画像は`.runtime/hunyuan-hole-check/`にあり、Gitには含めません。
既存の組立・関節・材料を変更していないため、CAD/STL・衝突・CalculiXの再ビルドは行っていません。
