# Bambu Connectの画面情報の検証

`tools/inspect_bambu_connect_ui.ps1` は Windows UI Automation で Connect の
現在の画面情報を読み取る診断ツールです。ウィンドウのアクティブ化、クリック、
キー入力、印刷送信は行いません。認証情報や入力欄の値も取得しません。
computer-use スキルには依存しません。

実行例（プロジェクトディレクトリ内）:

```powershell
./tools/inspect_bambu_connect_ui.ps1 -OutputPath .runtime/connect_test/ui-inspection.json
```

出力には画面のラベルが含まれます。ローカルの診断用途に限定し、HTTPで配信しません。
要素数と走査時間に上限があります。ただし Windows の個々の UI Automation 呼び出しが
応答しない場合は、別プロセスとして実行した診断側でタイムアウトを扱う必要があります。

## 画像認識の試作（同日21:28以降）

`tools/read_connect_screen.ps1` は対象プロセスを限定して `PrintWindow` でウィンドウ画像を取得し、
Windows 標準の英語 OCR で文字と位置を読み取ります。別アプリやデスクトップ全体は撮影しません。
最小化・非表示なら停止し、ウィンドウの移動やアクティブ化はしません。
Windows PowerShell 5.1 で実行します。OCR データはローカルの `.runtime/` に保存します。
取得に成功しても黒い画像などが返る可能性があるため、キャプチャ成功だけでは画面を認識したとは扱いません。

`tools/analyze_connect_screen.py` は上記ツールを呼び、画面と印刷設定の候補をまとめます。

固定の画面座標には依存しません。通常の全画面 OCR では Send が欠落したため、この処理を追加しました。
設定項目は文字位置と On / Off の文字色を組み合わせて読み取ります。


## Windows操作の高速化

- 1回の印刷実行内でPython解析とWindows OCRワーカーを使い回す。画像ごとのプロセス起動を廃止。
- 拡大したOCR用画像はメモリー上のBMPで受け渡し、PNG圧縮・保存・再読み込みを省略。
  元の画像と認識文字は引き続き記録。従来の単独PowerShell診断ではPNG出力を維持。
- ボタンの色判定は画像ライブラリ、連結領域の抽出は行単位の走査に変更。
- 再確認時も必ず新しく撮影する。画素が完全一致し、ウィンドウID・プロセスID等も一致した場合だけ
  直前の認識を再利用する。1画素の変化でも再認識し、保存画像をライブ証拠として使い回さない。
  設定ファイルの照合は再利用時も実行。元の認識画像と画素SHA-256も解析記録に残す。
- 最初の確認は即時実行し、画面が準備中の場合だけ50ms間隔で再確認する。
  Send画面はボタンと印刷先・設定がそろうまで待つ。待機の上限時間とクリックの1回制限を維持。
- クリック後の固定待機を90msから10msへ短縮。前面を切り替えるウィンドウラッパーの呼び出しを
  省き、直前の前面・画像照合後にpywinautoの公開mouse.clickを使用する。
- Send後の監視には45秒の時間上限を設け、認識が速くなったことで監視時間まで短縮しない。
