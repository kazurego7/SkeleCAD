# ジョイント加工の速度改善

## 加工をまたぐ関節CADキャッシュ

関節ごとのBREP・STEP・STLを `.runtime/workflow-cad-cache/` に保存する。
関節入力（計算元を示すラベルを除く）、全パラメータ、要求設定、全src Python
ファイルのハッシュ、toolchain設定、FreeCADバージョンが一致するときだけ再利用。
完成エントリーのみを利用し、全ファイルのSHA-256とBREPのCAD有効性を確認する。
破損を検出した場合は加工を停止する。関節ごとの結合・干渉・形状保持・STL検査は
従来どおり実施する。キャッシュはローカル生成物で公開対象外。

同じプテラノドンで、追加前23.26秒、初回保存25.96秒、6関節再利用18.25秒。
CAD工程は6.61秒から1.60秒。再加工全体で約22%短縮（少数回の実測）。
初回は保存負担があり、速度改善は主に同条件の再加工で得られる。
初回保存・再利用とも加工用36個と完成7部品のSTLが追加前と完全一致。
ジョイント記録・衝突結果も一致。別の検証用要求で1関節だけ0.1 mm動かした際は
その1関節を再生成し、残り5関節を再利用、未変更25個の工具STLが完全一致。
ユーザーの表示モデルや位置はこの検証で変更していない。

詳細: `.runtime/joint-cad-cache-comparison.json`。
再利用・破損拒否・設定/コード/位置変更時の無効化テストを追加。

同じC4ソケットのCAD原型を関節ごとに再計算せず、1回生成して個別にコピーする。
各コピーに従来どおりの位置・角度を適用する。原型は1回の加工要求内だけで
共有し、設定変更をまたいだ再利用はしない。

局所形状の照合では、三角形ごとのPythonループをNumPyの一括ソートへ変更した。
従来と同じfloat64・辞書順・ハッシュ入力バイト列を維持する。座標の丸め、
メッシュ簡略化、探索間隔や許容差の変更、検証の省略は行わない。

## 実測と精度確認（2026-09-05）

ユーザーのプテラノドン7部品・6関節で比較。全実行で既存の仕上げ・軸探索
キャッシュが利用可能な再加工条件。初回加工の速度や他モデルへの効果は未測定。

| 工程 | 変更前 | 変更後1回目 | 変更後2回目 |
| --- | ---: | ---: | ---: |
| 軸・固定位置処理 | 2.53秒 | 1.26秒 | 1.25秒 |
| ジョイントCAD生成 | 7.61秒 | 6.70秒 | 6.61秒 |
| 加工全体 | 25.70秒 | 23.80秒 | 23.26秒 |

変更後平均23.53秒、約8.4%短縮。少数回のローカル測定であり保証値ではない。
両実行とも完成7部品と加工用36個、計43個のSTLが変更前とバイト単位で一致。
ジョイント記録と衝突検査結果も一致。閉じた部品の検証・CAD出力検証を含む
通常の加工処理を通過した。加工関連20テスト、スリット対称性CADテスト成功。

詳細: `.runtime/joint-speed-comparison.json`。
今回形状・材料・組立に変更がないため、全体CAD再生成・CalculiX再実行はせず、
実加工の全出力比較で精度維持を確認した。表示中の同一形状の版は維持し、
次回の加工から新しい処理を使用する。
