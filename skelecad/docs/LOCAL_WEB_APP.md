# ローカルWebアプリの使い方

## 開く場所

- このPC: http://127.0.0.1:8765/viewer/
- Tailscale経由: https://YOUR-DEVICE.YOUR-TAILNET.ts.net/skelecad/

末尾の `/` がない `/skelecad` からも開けます。
旧 `/3dviewer` と、このビュワー用だった入口 `/` は移行時に解除します。

Tailscale側のアクセス権がある接続済み端末で開いてください。
このPCが起動し、スリープせず、ビュワーのサーバーが動いている必要があります。
入口にアクセスするとビュワーへ転送され、フォルダ一覧は表示しません。

## 関節を動かして衝突を確認

「新規モデル：ジョイント加工済み」は、パーツを直接つかんで動かせます。
色分けは常時オンです。凡例や関節操作カードは出さず、モデルを全面に表示します。

- パーツをドラッグすると、その関節が動きます。脚を動かすと足先も追従します。
- 背景や胴体をドラッグすると視点が回ります。Alt＋ドラッグでも視点を回せます。
- Shift＋ドラッグでねじり、矢印キーで選択した関節を微調整できます。
- ドラッグ中も衝突を判定し、食い込み箇所を赤い点で表示します。
  衝突したときだけ、画面上部に衝突しているパーツ名を表示します。
  赤い点は裏側のものも透かして表示します。
- Homeで選択した関節、Escで全体の姿勢を戻せます。

表面の点を調べる近似判定なので、細かな干渉を見逃す場合があります。
衝突表示が出なくても、実物の可動域や組付けを保証するものではありません。
±60°は画面上の操作範囲です。姿勢を動かしても印刷データは変更されません。

## PC再起動後の起動

従来の `0_3Dモデルをぐりぐり確認.lnk` で起動できます。
通常は8765を使い、使用中の場合は空きポートを探します。
起動時に表示されたURLを使ってください。ログイン時の自動起動は設定していません。

設定確認も含めて起動する場合は、skelecadフォルダで次を実行します。

```powershell
.\tools\open_3d_viewer.ps1 -Tailscale
```

PC側でブラウザを開かずに起動する場合:

```powershell
.\tools\open_3d_viewer.ps1 -Tailscale -NoBrowser
```

一度設定すると `.runtime/viewer-network.json` に接続方式を保存し、通常の起動でも
Tailscale設定を確認します。ルートの `start.ps1 -Tailscale` でも初期設定できます。
既存の `/skelecad` が別サービスを指す場合は上書きせずエラーにします。
旧 `/3dviewer` と `/` はこのビュワーを指していた場合だけ解除し、他アプリは保持します。
更新前またはローカル専用のサーバーが起動済みの場合は、実行中の生成・加工が完了してから
サーバーを終了し、`-Tailscale` を付けて起動し直してください。

## 公開範囲と保存

サーバーはPC内の127.0.0.1で待ち受け、Tailscale Serve経由で利用します。
インターネット一般公開用のFunnelは有効にしません。
画面、指定モデル、モデル設定のみ配信し、ブラウザプロファイルや
その他のプロジェクトファイル、フォルダ一覧は配信しません。

保存した姿勢スナップショットは同じブラウザのlocalStorageに残ります。
端末間では同期しません。未保存の操作は再読み込みで失われます。
画像ジョブ・分割指定・加工履歴はサーバーの`build/workflows/`に保存されます。
画像生成・加工・印刷APIは、このPCと起動時に確認したTailscaleホストから使用できます。
別ホスト・別オリジンのリクエストは拒否し、変更操作にはセッショントークンが必要です。
「プリント準備」で開くBambu Studioはサーバー側のPC上で動作します。

サーバーログは `.runtime/viewer.stdout.log` と `.runtime/viewer.stderr.log` に出ます。

## 配信の検証

工程の先行処理、連続編集時の採用条件、表示キャッシュについては
[WORKFLOW_PREFETCH.md](WORKFLOW_PREFETCH.md) を参照してください。

### 上り1〜2Mbpsでの表示

- HTML・JavaScript・設定・STLをgzip圧縮して配信します。STLの座標・面・精度は変えません。
- モデルのSHA-256をURLに含め、取得済みの同じデータをブラウザの通信キャッシュで再利用します。
  更新後は別URLになり、受信後にもハッシュを照合します。
- 画面ファイル・マニフェストはETagで更新確認し、変化がなければ本文を再送しません。
- Tailscale経由では別工程のモデルを先読みしません。モデルを切り替えると不要な取得を中断します。
- 一覧画像は最大320×240のJPEGを必要時に読み込み、元画像は画像工程を開いた時だけ取得します。
- 状態確認は処理中2秒、待機中10秒、画面が非表示なら30秒間隔です。

初回の大きいモデルの転送時間は回線速度に依存します。キャッシュが保持されている間、
2回目以降の同一モデルは本体を再送しません。CAD・印刷用出力は変更しません。

`tools/test_viewer_server.py` で入口・許可ファイル・gzipの完全復元・キャッシュ更新・
アクセス制限・サムネイルを、`viewer/tests/` で画面動作を検証します。
実際の配信量とモデルの完全一致は次で確認できます。

```powershell
..\.tools\python-runtime-3.14\Scripts\python.exe tools/check_remote_delivery.py https://YOUR-DEVICE.YOUR-TAILNET.ts.net/skelecad/viewer/
```

### スマホの操作

スマホ用の配置は `viewer/mobile.css` に分離し、PCでは従来の配置を使います。
縦画面は下部、横画面は右側に工程タブを配置します。既存の姿勢カードは下部で横にスクロールできます。
画像工程は画像エリアをタップして取り込みます。画像選択の隣の丸い「？」で、現在の工程の操作説明を開きます。

- パーツ分割：モデル表面を約0.6秒長押しでマーカー追加、既存マーカーを長押しで削除。
- 既存マーカーをダブルタップすると左右対称を切り替えます。対称ペアは従来どおり一緒に削除します。
- 指を8px以上動かす、2本指になる、工程を変える、操作が中断されると長押しを取り消します。
- 可動域：パーツを直接ドラッグして曲げる・外側をなぞってねじる。背景ドラッグは視点回転。
- 2本指で平行移動、ピンチで拡大縮小、ひねって視点を傾けます。
- 長押し時の文字選択と3D画面の標準メニューを抑止します。入力欄は通常どおり編集できます。

PCのダブルクリック・右クリック・ホイール操作は維持します。

スマホでは3D表示をヘッダー直下から工程タブまで広げ、表示リセットは3D領域の右上のアイコンに集約します。
スマホの工程タブは同じ幅の矢羽根形で、「パーツ／分割」「プリント／準備」の位置で2行にします。分割マーカーは画面上の投影サイズに応じて伸縮し、
スマホの一律44px制限を適用しません。PCのマーカーサイズ制限と操作配置は変更しません。

操作説明は「？」のモーダルにまとめ、スマホでは上部の通常案内とパーツ角度を表示しません。
状態メッセージは下部、姿勢カードがある場合はその上に配置します。エラー表示は残します。
ヘルプはスマホのタッチ操作とPCのマウス操作を切り替え、可動域からプリント準備の説明も開けます。
姿勢カードの削除ボタンは表示しません。スマホ・PCとも一覧内のドラッグで並べ替えます。
一覧の外縁から80px以上離れるとカードを赤くし、「離すと削除」を表示します。その位置で放したときだけ削除します。
一覧の近くで放すと元に戻り、一覧内へ戻して放すと並べ替えになります。複数指・操作中断・モデル変更では削除しません。
可動域の円はパーツの短辺に合わせて小さくし、円の外側をねじり操作として選びやすくしています。

工程名の位置を固定し、ロード中は矢羽根の輪郭を光が一周します。動きを減らす設定では輪郭を静止表示します。
エラー・警告マークは表示せず、色と下部メッセージで状態を示します。スマホのエラーは工程によらず表示領域の横幅を使います。

### 低帯域向けの軽量形状配信（2026-09-12）

localhost以外では、表示用の形状を表面の誤差を確認しながら簡略化し、頂点共有・バイト並べ替え・gzipで配信します。
部品や輪郭の細部は粗くなりますが、CAD・STL・3MFの原本や保存済みマーカーは変更しません。
`fast-simplification==0.2.0`を表示専用に使用します。生成物には書き込まず、配信キャッシュに保持します。

表示用は `?format=mesh-v1&detail=preview-v3`、精密形状は `?format=mesh-v1` です。
形式には原本のSHA-256を埋め込み、レスポンスのSHA-256で通信の完全性を確認します。
原本のハッシュ指定が古い場合は409とし、軽量形状を精密形状のキャッシュに混ぜません。
旧サーバーがSTLを返す場合にも読み込めます。ローカル表示は従来のSTLを使います。

モデル確認・パーツ分割では軽量表示だけを転送します。可動域では先に軽量表示を動かせる状態にし、
衝突判定用に原本と全頂点・面順序が一致する精密形状を裏で取得します。
精密形状の到着・衝突判定までは未確認として扱い、到着時も操作中の姿勢を維持します。
このため初回の可動域には追加の転送が発生します。判定結果と表示姿勢の同期は従来どおり維持します。
印刷用ファイルの精度・出力経路は変更しません。

配信量・元形状との一致・軽量形状の構造・キャッシュを `tools/check_remote_delivery.py` で確認できます。

簡略化は128面から始め、元形状と候補形状の表面を両方向にサンプリングして確認します。
基準は画像ジョブの作成時に決まる `target_length_mm` です。モデル・パーツ分割・可動域の全工程、全パーツで共通です。
99パーセンタイル誤差がこの全体寸法の0.15%以内、最大誤差が0.3%以内に収まるまで面数を増やします。
部品単位の大きさによる基準や、一律3,000面の下限は使いません。同じ形状は工程によらず同じ品質になります。
規定の面数で形状を保持できない場合は元の形状を採用します。これは表示品質のサンプル検査であり、厳密な形状誤差の保証ではありません。
モデルの全体寸法も配信キャッシュの識別に含め、ブラウザの軽量キャッシュもジョブごとに分離します。
表示URLを更新し、ユーザー依頼のキャッシュ更新として全スクリプト・スタイル・モデルURLの世代を変更しました。
サーバーのメモリキャッシュは再起動で破棄し、保存済みモデル・姿勢のローカルストレージは維持します。

2026-09-12の実モデル7部品では、表示用の圧縮転送量は合計204,601バイト（約205KB、21,536面）でした。
可動域の精密判定用データは別途4,155,147バイトです。Tailscale経由の配信検査と、
リモート画面で軽量表示・7部品の読み込み・精密衝突判定の完了を確認しました。
